# AGENTS.md — limbo-c++ (Minecraft Limbo backend, C++20)

## Build & test (no sudo, no cmake; needs g++>=12, make, OpenSSL libcrypto)

```sh
make                                   # builds build/limbo
make test                              # full gate: 12 unit suites + HMAC vector, all must pass
make build/test_play && ./build/test_play   # single suite (same pattern for all TEST_BINS in Makefile)
```

- **Header-only edits do NOT rebuild.** `build/limbo` depends only on `*.cpp` (`Makefile:21`), so after touching any `.h`, run `touch` on a dependent `.cpp` or `make clean` first. Same applies to `build/test_*` bins (each links only its listed sources).
- Test binaries are minimal links, not the full tree — e.g. `test_play` covers `play.cpp`, never `connection.cpp`. A green unit suite does not cover the server loop.

## Codegen — never hand-edit generated output

- `src/protocol/codec_data.{h,cpp}` is generated by `tools/gen_codec.py`, which reads `login_*.json` snapshots from `/tmp/opencode` (PrismarineJS/minecraft-data). If that dir is wiped, re-download the 14 files before regenerating.
- `tools/sound-variant-registries-26.1.nbt` (ViaVersion's file, checked in) feeds the 26.1+ sound-variant registry bodies via the same script.
- Fixture generators: `tools/gen_spawn_schem.py`, `tools/gen_we_schem.py` → `tests/data/`.

## Running the server

- Config resolution is binary-relative (`src/main.cpp`): `./limbo.properties` beside the binary wins, then `build/../config/limbo.properties`, then CWD `config/limbo.properties`. The startup `[config] file=` line tells you which one loaded.
- Start: `./build/limbo --config config/limbo.properties` (add `> log 2>&1 & echo $! > <pidfile>` for background runs).
- **Kill via exact PID from your pidfile. Never `pkill -f "build/limbo"`** — the pattern matches the invoking shell and kills your own session.
- Scratch space: use `/tmp/opencode` (pre-created, approved); don't scatter files in `/tmp`.

## Integration tests need a live server

`tests/integration/matrix.py`, `matrix_26x.py`, `hardening_matrix.py`, `status_ping.py`, `ipv6_status.py` open raw sockets to `127.0.0.1:25566` (args can override host/port). `tests/fuzz/fuzz_suite.py` + `fuzz_packet.py` are also run as part of verification. `tests/soak/` holds long-run soaks, not part of `make test`.

## Logging

`debug_level=error|info|debug|trace` (default `info`; legacy `debug_log=true` still maps to `debug`). Connections log their full story: `[login]` → `[leave] ... stage=<login|config|play> ... reason: ...`; rejects log `[reject]` with cause. When a real client fails, the client log line plus the server `[leave]` reason together identify the stage.

## Layout

- `src/main.cpp` → `server/tcp_server.{h,cpp}` (accept loop; owns the live player counter — status pings never touch it) → `server/connection.{h,cpp}` (handshake/login/config/play per connection).
- `src/protocol/`: `versions.h` (per-PVN eras/IDs — source of truth for packet IDs), `play.cpp` (JoinGame/position/chunk-adjacent bodies), `registry.cpp` (Configuration RegistryData/Tags/KnownPacks), `buffer.h`/`nbt.cpp` (wire primitives).
- `src/world/`: `void_chunk.cpp` (chunk bodies + schematic overlay, 1.18+ only) + `schematic.cpp` (Sponge `.schem` reader). `src/security/`: Velocity forwarding + rate limits. `src/server/skin.cpp`: offline skins (no Mojang calls anywhere by design).
- Protocol ground truth lives outside the repo: minecraft-data `protocol.json`/`loginPacket.json`, ViaVersion rewriter sources on GitHub, `minecraft.wiki` packet tables, and the local vanilla client jar (`~/.local/share/FreesmLauncher/.../minecraft-<ver>-client.jar` + `javap` for exact 26.x field order).

## Conventions

- Every source file carries the proprietary copyright header; `tools/add_copyright_header.py` enforces it.
- New behavior ships with asserts in the matching `tests/test_*.cpp` (append, don't rewrite existing checks).
- Docs that matter: `docs/ARCHITECTURE.md` (decisions), `docs/research/limbo-references.md` (protocol sources). `wiki/` + `mkdocs.yml` build the site; `tools/check_*.py` validate it.
